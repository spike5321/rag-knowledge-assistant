# 知识库构建工具 · 产品设计文档

版本：v0.2
日期：2026-09-21

## 1. 产品定位

**把一堆文档变成一个可检索的向量库。**

服务对象不是终端用户，而是**需要检索能力的 Agent 系统**。
它的主战场是 [MockMate](https://github.com/spike5321/mockmate)（自己实现调度循环的
面试 Agent），本仓库是那份检索层的独立可复用版本。

因此 v0.2 把主体从"界面"改成"命令行"：
`python -m rag.ingest` 建库、`python -m rag.query` 验证检索、Streamlit 界面是可选的核对工具。
F2/F3/F4 描述的问答链路继续保留，但定位是**验证检索质量的手段**，不是产品主体。

理由：这套能力真正的使用者是 Agent。单独做一个平行的问答应用，只会让人问
"它和 MockMate 的 `kb/` 是什么关系"。

## 2. 目标用户与场景

- 主要用户：需要给 Agent 接一套本地知识库的开发者（含我自己）
- 典型场景一：把一批 markdown 技术笔记建成库，Agent 出题/作答时按需检索
- 典型场景二：换了切分策略或 embedding 模型后，用 `rag.query` 直接对比同一问题的命中片段

## 3. 主要功能

### F1 文档入库（v0.2 重做）
- 支持 PDF / TXT / Markdown 三种格式，支持单个文件、目录（递归）与界面批量上传
- **先按 markdown 标题切小节**，小节内按段落聚合成约 500 字片段（相邻片段有重叠）；
  PDF 这类无空行文本退回按行切。片段前带上所属小节标题
- 向量化支持智谱 embedding-3 与本地 `bge-small-zh-v1.5`，**没配 API Key 也能跑**
- **幂等**：内容指纹一致就跳过，内容变了就覆盖旧片段（不再"同名文件一律跳过"）
- 单个文件失败不影响整批，失败原因逐条返回

### F2 检索验证
- `python -m rag.query "问题"` 只返回命中片段与相似度，**不调用大模型**
- 目的：把"切分/向量化的质量"和"生成的质量"分开看

### F3 引用溯源
- 每条回答下方展示引用片段：来源文件名、相似度分数、原文摘录
- 回答正文中以 [1] [2] 编号标注引用位置

### F4 对话界面（可选）
- Streamlit 聊天式界面，保留会话历史
- 侧边栏提供文档上传与入库入口

## 4. 明确不做（后续迭代）

- 混合检索（BM25）、Rerank、查询改写 —— 检索优化，留作改进故事
- 工具调用 / 联网搜索 —— 属于 Agent 项目（MockMate）的内容
- 用户系统、文档删除/管理后台
- 流式输出 —— 体验优化，v1.1

## 5. 技术选型

| 项 | 选择 |
|---|---|
| LLM | 智谱 glm-4-flash（免费） |
| Embedding | 智谱 embedding-3 |
| 向量库 | Chroma（本地持久化） |
| 界面 | Streamlit |
| 语言/测试 | Python 3.11 / pytest |

## 6. 非功能要求

- 全程本地运行，API Key 通过 `.env` 注入，不硬编码
- 切分等核心逻辑具备单元测试；外部 API 调用可 mock

## 7. 验收标准

1. 上传 PDF 与 Markdown 各一份，成功入库并显示片段数
2. 针对文档内容提问，回答准确且带引用来源
3. 问文档中不存在的内容时，模型明确说明资料未提及
4. 切分逻辑单元测试通过
5. README 步骤清晰，可按文档一键跑起

## 8. 演进路线（Roadmap）

- v1.1：流式输出、检索参数调优、失败重试
- v1.2：混合检索 + Rerank，RAGAS 检索质量评测报告
- v2.0：工具调用（联网搜索等），升级为 Agent；引入 LangGraph 编排
